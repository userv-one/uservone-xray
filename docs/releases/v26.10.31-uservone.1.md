# v26.10.31-uservone.1

Unified uservone Xray release for VLESS+Reality+XTLS Vision, Shadowsocks 2022, and SOCKS5. Assets include Linux AMD64 and ARM64 binaries, `SHA256SUMS`, `buildinfo.json`, and an SPDX SBOM.

## Compatibility and breaking changes

- VLESS, REALITY, XTLS Vision, Shadowsocks 2022, and SOCKS5 wire formats are unchanged. No protocol fork or client-side migration is required by the wire implementation. External production clients were not exercised by the release checks.
- The text version prefix is now `uservone Xray 26.10.31 ...`, not `Xray 26.7.28 ...` or upstream `Xray 26.10.31 ...`. Use `xray version-json` and its `name`, `version`, `build`, `go_version`, `os`, `arch`, and `upstream` fields instead of parsing the text line.
- TCP keepalive defaults are 60 seconds idle and 15 seconds between probes for both inbound and outbound connections. Upstream outbound defaults were 45/45; upstream inbound keepalive was disabled by default.
- SOCKS `auth` must be explicit. Missing or unknown values are rejected instead of silently enabling `noauth`. `password` requires at least one account. Explicit `noauth` remains available for trusted loopback configurations.

## uservone-platform migration

1. In `server/ssh.js`, set `XRAY_VERSION` to `v26.10.31-uservone.1`. Update `XRAY_INSTALL` and architecture selection to install the matching uservone release asset and verify it against `SHA256SUMS`; do not assume the official Xray-install script installs this fork.
2. Search with `grep -R "Xray 26.7.28" server` and update old version assertions. Prefer `version-json` over adding another text grep.
3. Update `server/nodeHealth.js` / `collectNodeFingerprint` to consume the machine-readable identity and the release commit recorded in `buildinfo.json`.
4. Update the drift baseline to the release commit from `buildinfo.json`; retain upstream baseline `1c8bf4067b881e5f21442882013d0617e4d5dc6d` for upstream comparisons.
5. Update `server/test-protocol-stability.mjs` for `uservone Xray`, the explicit SOCKS authentication requirement, and the health keys below.
6. Audit every other version check that expects `Xray ...`, `26.7.28`, or the previous drift baseline before deployment.

## VLESS + REALITY

The client fixture covers `xtls-rprx-vision`, `packetEncoding=xudp`, REALITY public key/short ID, SNI, fingerprint, and keepalive sockopt. The share-link fixture uses the XTLS share-link names `pbk`, `sid`, `fp`, `sni`, and `spx`; the JSON configuration retains `publicKey`, `shortId`, `fingerprint`, and `serverName`. `packetEncoding=xudp` is subscription metadata; the XUDP implementation and wire behavior remain upstream.

## Shadowsocks 2022

The `ss-in` fixture uses `2022-blake3-aes-128-gcm`, TCP and UDP on port 8388. Inject the production password from `proto_meta`; never log it.

The uservone-platform legacy SIP002 subscription format is intentionally unchanged:

```text
ss://<base64url(method:password)>@host:8388#label
```

For external clients that enforce the [AEAD-2022 SIP002 representation](https://shadowsocks.org/doc/sip002.html), `examples/uservone.shadowsocks-aead2022.url` provides the standards-compliant alternative with unencoded, percent-escaped userinfo:

```text
ss://2022-blake3-aes-128-gcm:BmtPW3egtT7pVAK9wpRzlg%3D%3D@host:8388#label
```

Do not replace the platform's legacy form during this migration; choose the standards-compliant form for clients that require it.

Expected independent health keys are `shadowsocks:tcp:8388` and `shadowsocks:udp:8388`. A failed UDP probe must not automatically revoke or mark down the TCP path.

## SOCKS5

The `socks-in` fixture uses RFC 1929 username/password authentication, UDP enabled, and port 1080. `deriveSocks5Credentials` in `server/xray.js` is intentionally unchanged:

- username: first 16 characters of the UUID after removing hyphens;
- password: first 16 hexadecimal characters of `SHA256("socks5:<uuid>")`.

`GET /api/account/telegram-proxies` must continue returning `host`, `port`, `username`, `password`, and `deepLink` with the existing semantics.

### Browser limitations

Chromium does not support SOCKS5 username/password authentication through `chrome.proxy`; use a local authentication helper or an HTTPS proxy. Firefox supports authenticated SOCKS through `ProxyInfo`.

## Rollback

Before replacing the binary or configuration:

```bash
sudo install -m 0755 /usr/local/bin/xray /usr/local/bin/xray.previous
sudo cp -a /usr/local/etc/xray/config.json /usr/local/etc/xray/config.json.previous
```

Install the new binary only after validating the new configuration:

```bash
./xray run -test -config /usr/local/etc/xray/config.json
```

To roll back:

```bash
sudo systemctl stop xray
sudo install -m 0755 /usr/local/bin/xray.previous /usr/local/bin/xray
sudo cp -a /usr/local/etc/xray/config.json.previous /usr/local/etc/xray/config.json
/usr/local/bin/xray run -test -config /usr/local/etc/xray/config.json && sudo systemctl start xray
```
